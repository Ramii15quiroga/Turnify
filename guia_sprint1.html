Guía de Puesta en Marcha Local

Comandos para instalar, poblar la base de datos y correr el sistema

Paso 1 · Instalación y Base de Datos

Instala los paquetes en monorepo, genera las migraciones de Prisma y corre la semilla inicial:

npm install
npm run setup
Paso 2 · Iniciar Servidores en Desarrollo

Levanta simultáneamente el Backend (puerto 4000) y el Frontend Vite (puerto 5173):

npm run dev

npm test

Arquitectura Técnica y Modelo de Datos

Cumplimiento estricto de Tercera Forma Normal (3FN) y prevención de duplicados

User Entidad de Cuentas
  • id (PK, string cuid)
  • name (string)
  • email (unique, string)
  • password (hash bcrypt)
  • role (CLIENT | ADMIN)
Service Catálogo de Servicios
  • id (PK, string cuid)
  • name (unique, string)
  • description (string)
  • durationMinutes (int)
  • isActive (boolean, default true)
BusinessSchedule Horarios de Atención
  • id (PK, string cuid)
  • dayOfWeek (int: 0=Dom ... 6=Sáb)
  • startTime (string HH:mm)
  • endTime (string HH:mm)
  • slotDurationMinutes (int)
  • isActive (boolean)
Appointment Turnos y Concurrencia
  • id (PK, string cuid)
  • userId (FK -> User)
  • serviceId (FK -> Service)
  • date (string YYYY-MM-DD)
  • time (string HH:mm)
  • status (CONFIRMED | CANCELLED | ...)
  • cancellationReason (string optional)

🛡️ Garantía de Unicidad y Prevención de Doble Reserva (SCRUM-14)

Las reservas se procesan dentro de una transacción atómica serializada (`prisma.$transaction`). Si dos clientes solicitan exactamente el mismo turno en el mismo milisegundo, la base de datos y el servidor conceden el turno únicamente a uno de ellos (201) y responden al segundo con 409 Conflict, alertando en pantalla y recargando los slots disponibles para que pueda elegir otro.
